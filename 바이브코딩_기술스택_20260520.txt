Database

PostgreSQL, MS-SQL 전용 작명 컨벤션
모든 이름을 소문자로 작성, snake_case
SQL 예약어를 이름으로 쓰기 금지
Table Name : prefix = t_
View Name : prefix = v_
Stored Procedure Name : prefix = [데이터베이스명약어]_ (예: monitoring_survey_verification = msv_)
Function Name : prefix = f_


Table의 Primary Key : id로 명명 하고, 각 Database 숫자타입중 가장큰 타입, 자동증가 형식 다른 Table에서 Foreign Key 형식으로 참조할때는 참조테이블명_id
절대 Foreign Key는 만들지 않는다.
Stored Procedure 에서 join으로 id가 여러번 호출 될때에도 "as 테이블명_id" 이렇게 사용 한다.
Timestamp/Date : _at
반드시 모든 Table에 "삭제여부 : delete_yn, 생성일시 : create_at, 수정일시 : update_at" 을 추가 한다.
제약 조건 작명 (Constraints - Optional)
시스템 자동 생성을 쓰지 않고 명시할 경우 다음 규칙을 따릅니다.
PK: pk_ + 테이블명 (예: pk_t_users)
FK: fk_ + 본테이블 + _ + 참조테이블 (예: fk_t_orders_t_users)
Unique: uk_ + 테이블명 + _ + 컬럼명 (예: uk_t_users_email)
Index: idx_ + 테이블명 + _ + 컬럼명 (예: idx_t_users_last_name)



Web Application

1. Modern Productivity (Python + React + Tailwind)
가장 추천하는 현대적인 풀스택 조합입니다. 스타일링과 비즈니스 로직 모두 생산성에 초점이 맞춰져 있습니다.

Frontend: React (Next.js 권장) + Tailwind CSS

Backend: FastAPI (Python)

Database: PostgreSQL

시너지 효과:

Tailwind의 Utility-first 방식은 디자인 파일 없이도 코딩 중에 즉시 UI를 구성할 수 있게 해줍니다.

FastAPI의 자동 API 문서화(Swagger)와 Tailwind의 직관적인 클래스명이 결합되어 개발 생산성이 극대화됩니다.

2. Robust Fullstack (C# + Tailwind)
ASP.NET MVC 환경에서도 Tailwind를 충분히 활용할 수 있습니다. 기존의 무거운 CSS 프레임워크(Bootstrap 등)를 대체하여 훨씬 세련된 UI를 만들 수 있습니다.

Frontend: Razor View (ASP.NET MVC) + Tailwind CSS

Backend: ASP.NET MVC (C#)

Database: MS-SQL

시너지 효과:

Razor View(.cshtml) 파일 내에서 Tailwind 클래스를 직접 사용하여, 별도의 복잡한 CSS 파일을 관리할 필요가 없어집니다.

빌드 도구(PostCSS 등)를 통해 사용하지 않는 CSS를 제거하면 결과물 용량이 매우 가벼워집니다.

3. High-End Enterprise (C# API + React + Tailwind)
안정적인 데이터 처리와 화려한 클라이언트 UI가 모두 필요한 경우입니다.

Frontend: React + Tailwind CSS + Headless UI

Backend: ASP.NET Web API (C#)

Database: MS-SQL 또는 PostgreSQL

시너지 효과:

Headless UI나 Radix UI 같은 라이브러리를 Tailwind와 함께 사용하면, 접근성이 보장된 고성능 컴포넌트를 빠르게 제작할 수 있습니다.

대규모 프로젝트에서 일관된 디자인 시스템(Design System)을 유지하기에 가장 유리한 구조입니다.
